# Миграции базы данных

Файлы миграций располагаются непосредственно в этом каталоге.

Формат имени:

- `000001_description.up.sql` — применить изменение;
- `000001_description.down.sql` — отменить изменение.

У каждой миграции должны быть оба файла с одинаковым номером и именем. Номера должны быть уникальными и задавать порядок применения.

Миграции выполняются при запуске приложения в транзакции PostgreSQL. Для сериализации одновременного запуска нескольких экземпляров используется PostgreSQL advisory lock.

Реестр применённых миграций хранится в таблице `schema_migrations`. SQL-файлы не должны содержать команд управления транзакциями (`BEGIN`/`COMMIT`), поскольку транзакцией управляет приложение.

Миграция `000003_add_30m_timeframe` расширяет существующие CHECK-ограничения таймфреймов, не удаляя пользовательские настройки, сигналы или курсоры. Её обратная миграция намеренно отказывается выполняться, пока в базе есть данные с таймфреймом `30`.

Миграция `000004_password_auth` отзывает прежние активные Telegram-доступы, чтобы все ранее зарегистрированные аккаунты прошли проверку общего пароля. Обратная миграция намеренно не восстанавливает старые флаги доступа: прежний allowlist не хранится в базе, поэтому доступы при откате нужно администрировать вручную.

Миграция `000006_higher_timeframe_trend_context` добавляет к сигналам сохранённый контекст старшего таймфрейма 4h. Старые сигналы получают `UNKNOWN`, поскольку их исторический 4h-контекст не восстанавливается автоматически.

Миграция `000008_spot_alerts` добавляет явные подписки на Spot-уведомления, журнал обнаруженных движений и устойчивую очередь персональных Telegram-доставок. Отписка отменяет ещё не отправленные Spot-уведомления и не затрагивает RSI-доставку.
