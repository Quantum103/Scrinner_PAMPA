# Volume Trader

Самостоятельный сервис на Go для получения публичных рыночных данных Bybit USDT Perpetual (Linear), анализа торгового потока и формирования информационных сигналов входа LONG. Реальное исполнение ордеров не реализовано.

## Источники данных

### REST API

Используется `https://api.bybit.com`:

- `GET /v5/market/instruments-info` — активные USDT Linear Perpetual-контракты, пагинация по `nextPageCursor`, фильтрация по типу и статусу контракта.
- `GET /v5/market/tickers` — цена, best bid/ask, 24-часовые объём и оборот, изменение цены и funding.
- Дополнительные спецификации контракта: `minOrderQty`, `qtyStep`, `minNotionalValue`, `tickSize`, лимиты рыночного ордера и интервал funding.

`volume24h` используется только для предварительной оценки ликвидности. Он не подменяет RVOL.

### Публичный WebSocket

Endpoint: `wss://stream.bybit.com/v5/public/linear`.

Для каждого символа подписки:

- `publicTrade.{symbol}` — сделки: цена, количество, сторона агрессора (`Buy`/`Sell`), время биржи и ID.
- `orderbook.50.{symbol}` — 50 уровней bid/ask.

Стакан считается доступным только после snapshot. Snapshot полностью заменяет локальную книгу; delta изменяет уровни, а размер `0` удаляет уровень. Delta без snapshot, `u=1`, регрессия sequence, пересечённый стакан и некорректные уровни инвалидируют книгу до нового корректного snapshot. Устаревшие и повторные update ID не продлевают срок актуальности.

Соединения отправляют heartbeat каждые 20 секунд, имеют read/write deadlines и переподключаются с экспоненциальной задержкой. После переподключения подписки отправляются повторно. Символы делятся на группы с ограничением конфигурации. Подписки обновляются при изменении списка инструментов.

Сообщения WebSocket обрабатываются синхронно. Для сделок дополнительно ведётся ограниченный кольцевой буфер, а повторные trade ID отбрасываются. Переполнение, переподключение или разрыв потока помечают историю как неполную. Данные такого символа нельзя использовать как готовый сигнал до восстановления непрерывной истории.

## Анализ рыночных данных

В `Store.ApplyTrades` подключён один общий анализатор на каждый символ. Каждая новая уникальная сделка обновляет все показатели; отдельные анализаторы и промежуточные lossy-каналы не используются.

- **RVOL:** объём текущей части интервала делится на средний объём такой же по длительности части предыдущих 20 завершённых минутных интервалов. Например, первые 30 секунд текущей минуты сравниваются с первыми 30 секундами каждой из 20 предыдущих минут. Нужна непрерывная история; суточный объём не участвует.
- **Taker Buy/Sell:** объёмы и доли агрессивных покупок и продаж рассчитываются по `Side` сделки Bybit.
- **Delta:** `BuyVolume - SellVolume` за окно потока.
- **CVD:** скользящая сумма Delta за `ANALYSIS_CVD_WINDOW` (по умолчанию 15 минут). История очищается при старте новой сессии, переподключении или обнаруженном разрыве данных; автоматического сброса в полночь нет.
- **Momentum:** процентное изменение цены за каждый интервал из `ANALYSIS_MOMENTUM_WINDOWS`.
- **Volume acceleration:** отношение объёма текущего окна к объёму предыдущего равного окна.
- **Orderbook:** спред между best ask и best bid, а также доступная котируемая ликвидность на заданном числе ближайших уровней каждой стороны.
- **Absorption:** потенциальное поглощение покупок — высокая доля taker-buy, их объём выше предыдущего равного окна на заданный множитель, но цена при этом почти не растёт. Это наблюдение, не торговый сигнал.

У анализатора есть статусы `ready`, `insufficient_data`, `stale`, `incomplete`, `disconnected`. При нехватке истории или недостоверном состоянии источника значение не подменяется нулём или оценкой. После переподключения база RVOL и окна CVD должны накопиться заново.

### Начальные параметры анализа

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `ANALYSIS_RVOL_INTERVAL` | `1m` | Длина интервала RVOL |
| `ANALYSIS_RVOL_LOOKBACK_INTERVALS` | `20` | Число завершённых интервалов базы RVOL |
| `ANALYSIS_FLOW_WINDOW` | `1m` | Окно taker flow и Delta |
| `ANALYSIS_CVD_WINDOW` | `15m` | Скользящее окно CVD |
| `ANALYSIS_MOMENTUM_WINDOWS` | `15s,1m,5m` | Интервалы Momentum |
| `ANALYSIS_VOLUME_ACCELERATION_WINDOW` | `10s` | Окно для сравнения объёма |
| `ANALYSIS_ABSORPTION_MIN_BUY_SHARE` | `0.70` | Минимальная доля taker-buy |
| `ANALYSIS_ABSORPTION_BUY_VOLUME_MULTIPLIER` | `1.5` | Рост buy-объёма к предыдущему окну |
| `ANALYSIS_ABSORPTION_MAX_PRICE_CHANGE_PERCENT` | `0.05` | Максимальное изменение цены для absorption, % |
| `ANALYSIS_ORDERBOOK_LEVELS` | `10` | Число уровней ликвидности с каждой стороны |

Остальные параметры подключения и источников см. в `.env.example`: REST/WS URL, число отслеживаемых инструментов, WebSocket depth, группировка подписок, возраст данных и размеры буферов.


## Стратегия поиска входа (только LONG)

В `Store` после каждого принятого обновления сделки или стакана используется уже рассчитанный общий срез анализатора. Стратегия не пересчитывает RVOL/Delta/CVD отдельными обработчиками и не отправляет ордера. При выполнении критериев она создаёт информационный сигнал LONG, сохраняет последние сигналы в ограниченной памяти по каждому символу и выводит новый сигнал в лог.

Базовые фильтры:

- RVOL не ниже `ENTRY_MIN_RVOL` (по умолчанию 3).
- Доля taker-buy не ниже `ENTRY_MIN_TAKER_BUY_SHARE_PERCENT` (65%), Delta положительная, CVD положительный и растущий относительно предыдущего подтверждённого наблюдения.
- Momentum за `ENTRY_PRICE_CHANGE_WINDOW` не выше `ENTRY_MAX_PRICE_CHANGE_PERCENT` (1.5%). Окно должно присутствовать в `ANALYSIS_MOMENTUM_WINDOWS`.
- Absorption отсутствует; спред, bid/ask-ликвидность и число уровней стакана удовлетворяют заданным минимумам.
- В окне taker-потока есть минимум заданного числа сделок, а доля крупнейшей сделки не превышает `ENTRY_MAX_SINGLE_TRADE_SHARE_PERCENT`. Это ограничивает влияние одиночной крупной сделки.
- Все условия должны выполняться `ENTRY_CONFIRMATION_OBSERVATIONS` последовательных наблюдений с заданной частотой. Слишком большой интервал между наблюдениями сбрасывает подтверждение.

После сигнала действует `ENTRY_SIGNAL_COOLDOWN`. Повторная активация возможна только после указанного количества неуспешных наблюдений и завершения cooldown. При статусах анализатора, отличных от `ready`, разрыве потока, устаревшем стакане или неактуальной последней сделке вход блокируется.

### Параметры стратегии

Все значения ниже — стартовые гипотезы для тестирования, а не доказательство прибыльности.

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `ENTRY_STRATEGY_ENABLED` | `true` | Включить поиск сигналов |
| `ENTRY_MIN_RVOL` | `3` | Минимальный RVOL |
| `ENTRY_MIN_TAKER_BUY_SHARE_PERCENT` | `65` | Минимальная доля агрессивных покупок, % |
| `ENTRY_MAX_PRICE_CHANGE_PERCENT` | `1.5` | Максимальный рост цены за рассматриваемое окно, % |
| `ENTRY_PRICE_CHANGE_WINDOW` | `5m` | Окно Momentum; должно быть в `ANALYSIS_MOMENTUM_WINDOWS` |
| `ENTRY_MAX_SPREAD_BPS` | `15` | Максимальный спред, базисные пункты |
| `ENTRY_MIN_BID_LIQUIDITY_QUOTE` | `5000` | Минимальная ликвидность bid в USDT |
| `ENTRY_MIN_ASK_LIQUIDITY_QUOTE` | `5000` | Минимальная ликвидность ask в USDT |
| `ENTRY_MIN_BOOK_LEVELS` | `5` | Минимум уровней на каждой стороне стакана |
| `ENTRY_MIN_TRADES_IN_FLOW_WINDOW` | `5` | Минимум сделок в окне taker-потока |
| `ENTRY_MAX_SINGLE_TRADE_SHARE_PERCENT` | `35` | Максимальная доля крупнейшей сделки, % |
| `ENTRY_CONFIRMATION_OBSERVATIONS` | `3` | Число последовательных подтверждений |
| `ENTRY_OBSERVATION_INTERVAL` | `1s` | Минимальный интервал между наблюдениями |
| `ENTRY_MAX_OBSERVATION_GAP` | `3s` | Максимальный разрыв между последовательными наблюдениями |
| `ENTRY_SIGNAL_COOLDOWN` | `1m` | Пауза перед повторным сигналом |
| `ENTRY_REARM_OBSERVATIONS` | `2` | Сколько неуспешных наблюдений нужно для повторной активации |
| `ENTRY_SIGNAL_HISTORY_LIMIT` | `20` | Размер истории сигналов на символ |

Сигнал сохраняет символ, направление, цену, время, RVOL, Taker Buy (% и объём), Delta, CVD, изменение цены и его окно, спред, ликвидность с обеих сторон и объяснение причин. История пока оперативная (память процесса); после перезапуска она очищается.

## Paper Trading: виртуальный счёт и исполнение

Paper Trading включён по умолчанию и не отправляет реальные ордера. Он использует только публичный REST и публичный WebSocket-стакан Bybit. В \`internal/paper\` нет сетевого клиента. Публичный REST-клиент проекта выполняет только GET-запросы рыночных данных; приватный API, API-ключи и методы размещения ордеров не используются.

### Начальный риск и размер позиции

Параметры по умолчанию: 10 USDT, целевой риск 2,5% капитала, предельный риск 3% с учётом ожидаемой комиссии и проскальзывания, максимум 2x, на маржу выделяется не более 50% капитала, одна позиция, первоначальный trailing stop 2,5%.

Расчёт размера выполняется от расстояния между оценочной ценой входа и ожидаемой ценой выхода по начальному стопу. В расчёт на единицу количества входят:
- движение от фактической оценки VWAP входа до stop trigger;
- ожидаемое проскальзывание на входе и выходе;
- комиссия входа и ожидаемая комиссия выхода.

Размер дополнительно ограничивается свободной маржой, максимальной долей маржи, плечом и \`maxMktOrderQty\`. Количество округляется по \`qtyStep\`. Минимальный объём рассчитывается с учётом одновременно \`minOrderQty\` и \`minNotionalValue\`. Если минимально допустимый ордер требует расчётный риск выше 3% капитала или не помещается в лимит маржи, сделка отклоняется. Если доступной глубины не хватает на весь запланированный объём, допускается частичное исполнение, но только если фактически исполненная часть соблюдает ограничения контракта и риск.

### Виртуальное исполнение и сопровождение

- LONG-вход последовательно потребляет уровни Ask, LONG-выход — Bid.
- Средневзвешенная цена исполнения рассчитывается по фактически потреблённой глубине стакана. Настроенное проскальзывание добавляется поверх VWAP: вверх для покупки и вниз для продажи.
- Частичный выход уменьшает позицию и зарезервированную маржу. Остаток закрывается по следующим актуальным Bid; новая позиция до полного закрытия не открывается.
- Начальный stop устанавливается сразу после входа на 2,5% ниже фактической цены входа. При движении цены вверх stop следует за максимумом и никогда не опускается. Срабатывание проверяется по доступному Bid; закрытие моделируется прохождением по Bid-уровням.
- Funding применяется, если позиция пересекает \`nextFundingTime\`. Используются последние публичные \`fundingRate\` и \`markPrice\` из REST-тикера Bybit (не best Bid). Для линейного USDT-контракта сумма равна \`markPrice × quantity × fundingRate\`; положительная ставка является расходом LONG, отрицательная — поступлением. Если Mark Price устарел к моменту расчёта, settlement помечается как пропущенный, а не рассчитывается по Bid. Если funding-поля контракта отсутствуют или некорректны, новые позиции по нему не открываются.
- Комиссия входа списывается при открытии, комиссия выхода — при закрытии. Реализованный PnL включает уплаченные комиссии и funding; нереализованный PnL оценивается по текущему лучшему Bid.

Баланс, свободная и зарезервированная маржа, нереализованный и реализованный PnL, комиссии, funding и открытая позиция доступны через \`Store.PaperSnapshot\` и в \`PaperAccount\` снимка символа. Состояние хранится в памяти и исчезает после перезапуска.

### Параметры Paper Trading

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| \`PAPER_TRADING_ENABLED\` | \`true\` | Включить виртуальную торговлю |
| \`PAPER_INITIAL_BALANCE_USDT\` | \`10\` | Начальный виртуальный капитал |
| \`PAPER_TARGET_RISK_PERCENT\` | \`2.5\` | Целевой риск одной сделки, % капитала |
| \`PAPER_MAX_RISK_PERCENT\` | \`3\` | Жёсткий предел риска с учётом издержек |
| \`PAPER_MAX_LEVERAGE\` | \`2\` | Максимальное плечо |
| \`PAPER_MAX_MARGIN_PERCENT\` | \`50\` | Максимальная доля капитала под маржу |
| \`PAPER_MAX_OPEN_POSITIONS\` | \`1\` | Максимум открытых позиций; конфигурация выше 1 отклоняется |
| \`PAPER_TRAILING_STOP_PERCENT\` | \`2.5\` | Начальное расстояние trailing stop |
| \`PAPER_FEE_RATE\` | \`0.00055\` | Расчётная комиссия за сторону, доля от номинала |
| \`PAPER_SLIPPAGE_BPS\` | \`5\` | Расчётное проскальзывание на исполнение, базисные пункты |

Значения комиссии и проскальзывания — только стартовые предположения симуляции, не фактические тарифы аккаунта. Их следует заменить на свои реальные значения. Старые \`TRADING_FEE_RATE\` и \`SLIPPAGE_BPS\` поддерживаются как fallback, если новые \`PAPER_*\` переменные не заданы.

## Запуск

Требуется Go 1.23+.

```sh
cp .env.example .env
# Заполнить значения при необходимости. API-ключ Bybit не нужен.
go run ./cmd/volume-trader
```

PowerShell:

```powershell
Copy-Item .env.example .env
Get-Content .env | ForEach-Object {
    if ($_ -match '^\s*([^#][^=]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($matches[1].Trim(), $matches[2].Trim(), 'Process')
    }
}
go run ./cmd/volume-trader
```

## Проверки

```sh
gofmt -w ./cmd ./internal
go test ./...
go test -race ./...
go vet ./...
go build ./...
```

Тесты используют искусственные сообщения Bybit и поддельный транспорт для проверки логики WebSocket, snapshot/delta, переподключения и показателей анализа. Для полной интеграционной проверки необходимо запускать с доступом к настоящей зависимости Gorilla WebSocket и сети Bybit.

## Пока не реализовано

- Реальное исполнение ордеров, API-ключи и приватный WebSocket.
- Персистентное хранение истории сигналов между перезапусками.
- Telegram-уведомления.
