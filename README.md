# Volume Trader

Самостоятельный Go-сервис для получения публичных рыночных данных Bybit USDT Perpetual (Linear). Проект не использует и не изменяет код `Quantum103/scrinner`.

## Текущий этап

Сервис получает список активных USDT perpetual-контрактов и рыночные тикеры через публичный REST API Bybit V5.

Реализовано:

- Получение спецификаций через `GET /v5/market/instruments-info`.
- Пагинация по `nextPageCursor` до последней страницы. Лимит одной страницы — 1000 записей; искусственного ограничения в 500 записей или 20 страниц нет.
- Фильтрация только по `contractType=LinearPerpetual`, `status=Trading`, `quoteCoin=USDT` и `settleCoin=USDT`. Последние два поля фильтруются локально по ответу API.
- Получение тикеров через `GET /v5/market/tickers?category=linear`.
- Объединение спецификаций и тикеров по символу контракта.
- Периодическое обновление списка контрактов и рыночных данных с независимыми интервалами.
- Повторные попытки при временных сетевых ошибках, HTTP 429/5xx и временных кодах API Bybit.
- Учёт `Retry-After` и `X-Bapi-Limit-Reset-Timestamp`, ограничение частоты запросов клиента.
- Корректная остановка по сигналу ОС.

API-ключи не нужны. Клиент выполняет только публичные GET-запросы. Приватных и торговых endpoint в проекте нет.

## Рыночные данные

Для каждого контракта доступны:

- последняя цена;
- лучшая цена bid и ask;
- объём за 24 часа (`volume24h`);
- оборот за 24 часа (`turnover24h`);
- изменение цены за 24 часа (`price24hPcnt`);
- текущая ставка funding (`fundingRate`);
- время следующего funding (`nextFundingTime`).

`price24hPcnt` приходит как доля: например, `0.01` означает изменение на 1%. Для отображения в процентах значение можно умножить на 100.

Важно: `volume24h` — это обычный объём за последние 24 часа, а не Relative Volume. Его можно использовать как предварительный фильтр ликвидности. Анализ относительного объёма и торгового импульса здесь не реализован.

## Спецификации контрактов

Из `priceFilter`, `lotSizeFilter` и объекта контракта сохраняются:

| Поле | Назначение |
|---|---|
| `minOrderQty` | Минимальное количество в ордере |
| `qtyStep` | Шаг количества |
| `minNotionalValue` | Минимальная стоимость ордера |
| `tickSize` | Шаг цены |
| `maxMktOrderQty` | Максимальное количество для рыночного ордера |
| `fundingInterval` | Интервал funding в минутах |

Значения количества, цены и стоимости хранятся строками, чтобы не терять десятичную точность. Значения не задаются глобально: они читаются отдельно для каждого контракта из API.

## Обновление и ограничения API

По умолчанию:

- рыночные тикеры обновляются каждые 2 секунды;
- список контрактов и их спецификации обновляются каждые 15 минут;
- между HTTP-запросами одного клиента выдерживается интервал не менее 200 мс;
- используется ограниченное число повторных попыток с экспоненциальной задержкой;
- при наличии заголовков сервера учитываются `Retry-After` и время сброса лимита Bybit.

Если обновить список контрактов не удалось, сервис продолжает использовать предыдущий успешно полученный список и повторяет попытку с увеличивающейся задержкой. При первой неудачной загрузке список останется пустым до успешного ответа.

## Запуск

Требуется Go 1.23 или новее.

Склонируйте репозиторий и перейдите в его каталог:

```sh
git clone https://github.com/Quantum103/Scrinner_PAMPA.git
cd Scrinner_PAMPA
```

### PowerShell

```powershell
Copy-Item .env.example .env
Get-Content .env | ForEach-Object {
    if ($_ -match '^\s*([^#][^=]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($matches[1].Trim(), $matches[2].Trim(), 'Process')
    }
}
go run ./cmd/volume-trader
```

### Linux / macOS

```sh
cp .env.example .env
set -a
. ./.env
set +a
go run ./cmd/volume-trader
```

Для проверки старта без сетевых запросов:

```powershell
$env:MARKET_DATA_ENABLED = "false"
go run ./cmd/volume-trader
```

Остановить сервис можно через `Ctrl+C`.

Приложение читает переменные окружения напрямую и не загружает файл `.env` самостоятельно. Секреты и локальные настройки не должны попадать в Git; `.env` находится в `.gitignore`.

## Настройки

| Переменная | Значение по умолчанию | Описание |
|---|---:|---|
| `APP_LOG_LEVEL` | `info` | Уровень логирования: debug/info/warn/error |
| `BYBIT_REST_URL` | `https://api.bybit.com` | Публичный REST endpoint |
| `BYBIT_PUBLIC_WS_URL` | `wss://stream.bybit.com/v5/public/linear` | Адрес публичного WebSocket для следующего этапа; соединение ещё не реализовано |
| `MARKET_DATA_ENABLED` | `true` | Включает получение рыночных данных |
| `DATA_UPDATE_INTERVAL` | `2s` | Интервал получения тикеров |
| `INSTRUMENT_REFRESH_INTERVAL` | `15m` | Интервал обновления списка контрактов и спецификаций |
| `MAX_TRACKED_CONTRACTS` | `100` | Максимум контрактов, передаваемых дальше в текущий сборщик |
| `STRATEGY_VOLUME_MULTIPLIER` | `2.0` | Резервный параметр стратегии |
| `STRATEGY_TRAILING_STOP_PERCENT` | `2.5` | Резервный параметр стратегии |
| `STRATEGY_REVERSAL_CONFIRMATIONS` | `2` | Резервный параметр стратегии |
| `VIRTUAL_DEPOSIT_USDT` | `10` | Начальный виртуальный депозит |
| `RISK_PER_TRADE_PERCENT` | `1` | Резервный параметр риск-менеджмента |
| `MAX_OPEN_POSITIONS` | `1` | Резервный параметр риск-менеджмента |
| `TRADING_FEE_RATE` | `0.00055` | Предположение о комиссии за одну сторону будущей симуляции |
| `SLIPPAGE_BPS` | `5` | Предположение о проскальзывании для будущей симуляции |
| `TELEGRAM_BOT_TOKEN` | пусто | Резерв для будущего Telegram-бота |
| `TELEGRAM_CHAT_ID` | пусто | Резерв для будущего Telegram-бота |

Комиссия и проскальзывание сейчас только хранятся в конфигурации и не применяются к сделкам: торговая симуляция не реализована.

## Что пока не реализовано

- WebSocket-подключение и поток сделок/стакана.
- Анализ объёмов, Relative Volume и торгового импульса.
- Торговая стратегия и сигналы.
- Виртуальные ордера, позиции и расчёт PnL.
- Реальная торговля и приватные API.
- Отправка сообщений Telegram.
