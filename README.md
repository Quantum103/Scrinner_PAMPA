# Volume Trader

Самостоятельный Go-сервис для получения публичных рыночных данных Bybit USDT Perpetual (Linear). Проект не использует и не изменяет код `Quantum103/scrinner`.

## Что реализовано

### Публичный REST API

- Получение списка активных USDT perpetual-контрактов через `GET /v5/market/instruments-info`.
- Пагинация по `nextPageCursor` до последней страницы.
- Фильтрация по `contractType=LinearPerpetual`, `status=Trading`, `quoteCoin=USDT` и `settleCoin=USDT`.
- Загрузка цен, best bid/ask, объёма, оборота, изменения цены за 24 часа и funding через `GET /v5/market/tickers`.
- Получение индивидуальных спецификаций каждого контракта: `minOrderQty`, `qtyStep`, `minNotionalValue`, `tickSize`, `maxMktOrderQty`, `fundingInterval`.
- Повторные запросы при временных ошибках и ограничениях API.

`volume24h` — обычный объём за последние 24 часа, а не Relative Volume. Он пригоден для предварительного фильтра ликвидности. Анализ импульса и Relative Volume не реализован.

### Публичный WebSocket API

Используется только публичный endpoint:

`wss://stream.bybit.com/v5/public/linear`

На каждый инструмент оформляются две подписки:

- `publicTrade.{symbol}` — сделки с ценой, количеством, стороной агрессора (`Buy`/`Sell`), временем исполнения и ID сделки.
- `orderbook.50.{symbol}` — 50 уровней bid и ask.

Из стакана доступны отсортированные bids/asks, best bid, best ask, update ID, sequence, время биржи и локальное время получения.

#### Обработка стакана

1. До получения snapshot стакан считается недоступным.
2. Каждый новый snapshot полностью заменяет локальные bids и asks, даже если update ID сбросился после перезапуска сервиса Bybit.
3. Delta применяется только к восстановленному стакану.
4. Новые уровни добавляются, существующие обновляются.
5. Уровень с количеством `0` удаляется.
6. Устаревшее сообщение, уменьшение sequence, некорректная цена/величина, пустая сторона или пересечение best bid/ask инвалидируют стакан.
7. Delta без snapshot и delta с `u=1` требуют нового snapshot: текущий стакан использовать нельзя.
8. Повторная delta с уже обработанным update ID игнорируется и не обновляет время актуальности.

Цены хранятся и сравниваются с десятичной точностью. В локальной книге остаются максимум 50 лучших уровней каждой стороны.

#### Переподключение и подписки

- Heartbeat отправляется каждые 20 секунд.
- Для чтения установлен таймаут 60 секунд; входящие pong и сообщения обновляют срок чтения.
- При разрыве, ошибке протокола или невалидном delta соединение закрывается и восстанавливается с экспоненциальной задержкой от 1 до 30 секунд.
- После каждого переподключения все подписки соответствующего соединения отправляются заново.
- Список инструментов можно обновлять во время работы. Изменение списка пересобирает группы соединений; старые книги становятся недоступными до нового snapshot.
- На одном соединении не более 25 инструментов (50 тем: publicTrade + orderbook).
- В одном subscribe-запросе не более 10 аргументов; между пакетами выдерживается пауза 100 мс.

По документации Bybit публичные аргументы одного соединения ограничены общей длиной 21 000 символов. Для Futures ограничение в 100 аргументов на соединение указано с датой вступления в силу 26 ноября 2026 года. Текущая конфигурация использует 50 аргументов на соединение и остаётся ниже этого порога. При стандартном лимите `MAX_TRACKED_CONTRACTS=100` создаются четыре WebSocket-соединения, а не одно соединение на сотни инструментов.

#### Потеря данных и пригодность инструмента

WebSocket-сообщения обрабатываются синхронно в цикле чтения. Промежуточного канала, который мог бы незаметно переполниться, нет.

Сделки складываются в ограниченный кольцевой буфер каждого символа. Повторные ID отбрасываются. Если буфер переполняется, счётчик `DroppedTrades` увеличивается и выставляется признак `TradeGap`. При отключении и переподключении также выставляется `TradeGap`, поскольку за время разрыва могли пройти сделки, которые клиент не получил.

Снимок `Store.Snapshot(symbol, now)` помечает `UsableForSignal=true` только когда одновременно выполнены все условия:

- соединение активно;
- стакан восстановлен snapshot и не устарел;
- последняя сделка и её биржевое время не устарели;
- нет неподтверждённого разрыва истории сделок.

Максимальный возраст данных по умолчанию — 5 секунд. При переполнении кольцевого буфера downstream-сделок выставляются счётчик потерь и `TradeGap`; синхронный анализатор к этому моменту уже получил событие и не теряет его. После переподключения или реального разрыва сам анализатор очищает окна CVD и требует заново собрать непрерывную историю. До следующего этапа стратегии ни один сигнал не генерируется.

### Анализатор рыночных данных

В `Store.ApplyTrades` встроен один общий анализатор на инструмент. Каждая новая уникальная сделка из `publicTrade` сразу обновляет его агрегаты. Показатели не рассчитываются независимыми обработчиками и не зависят от чтения кольцевого буфера сделок. Для временных расчётов используются агрегаты с разрешением 100 мс; минутные объёмы RVOL ведутся отдельно.

#### Relative Volume (RVOL)

По умолчанию используется минутный интервал и последние 20 **завершённых** минут в качестве базы:

`RVOL = объём текущей части минуты / средний объём такой же по длительности части предыдущих 20 завершённых минут`.

Например, на 30-й секунде текущей минуты анализатор сравнивает её первые 30 секунд с первыми 30 секундами каждой из 20 завершённых минут. Так сравниваются сопоставимые по длительности отрезки, а не неполная текущая минута с полными прошлыми минутами. Нулевые отрезки без сделок учитываются как нулевой объём, только если WebSocket-поток оставался непрерывным. Если средний базовый объём равен нулю или нет полной истории, RVOL не возвращается. Суточный `volume24h` в формуле не участвует.

#### Taker flow, Delta и CVD

Сторона агрессора берётся непосредственно из `Side` сделки Bybit: `Buy` учитывается как taker-покупка, `Sell` — как taker-продажа. В окне `ANALYSIS_FLOW_WINDOW` рассчитываются объёмы покупок и продаж, доли в процентах и `Delta = BuyVolume - SellVolume`.

CVD — сумма `BuyVolume - SellVolume` за скользящее окно `ANALYSIS_CVD_WINDOW` (по умолчанию 15 минут). Старые сделки автоматически перестают входить в сумму по мере выхода из окна. CVD сбрасывает историю при старте новой WebSocket-сессии, переподключении или обнаруженном разрыве потока. Это не суточный CVD и у него нет автоматического сброса в полночь.

#### Momentum и ускорение объёма

Momentum для каждого заданного интервала — процентное изменение последней цены относительно последней известной цены на момент не позднее начала этого интервала. Интервалы задаются списком `ANALYSIS_MOMENTUM_WINDOWS`.

Volume acceleration сравнивает объём текущего окна с предыдущим окном той же длины:

`((текущий объём / предыдущий объём) - 1) × 100%`.

Если в предыдущем окне не было объёма или не хватает полной истории, значение не подставляется.

#### Стакан и absorption

- `SpreadBPS` — спред между best ask и best bid относительно средней цены, в базисных пунктах.
- `BidLiquidityQuote` и `AskLiquidityQuote` — сумма `price × size` по N ближайшим уровням каждой стороны. Это оценка котируемой ликвидности в USDT-эквиваленте, а не гарантия исполнения по этой цене.
- `Absorption=true` выставляется, когда одновременно выполнены все настроенные условия: доля taker-покупок достигает порога, их объём превышает объём покупок в предыдущем равном окне на заданный множитель, а абсолютное изменение цены за flow-окно остаётся ниже порога. Это только признак возможного поглощения покупок, а не подтверждённый сигнал на сделку.

#### Статусы данных

Анализ доступен в `SymbolSnapshot.Analysis`:

| Статус | Значение |
|---|---|
| `ready` | Все показатели рассчитаны на полной и актуальной истории. |
| `insufficient_data` | Идёт первичный сбор истории или для отдельных метрик пока недостаточно наблюдений; недоступные значения остаются `null`/отсутствуют. |
| `stale` | Последняя сделка или стакан старше `WS_MAX_DATA_AGE`; числовые метрики не возвращаются. |
| `incomplete` | Был разрыв потока или некорректное состояние стакана; метрики не возвращаются. После разрыва сделки собираются заново, при ошибке стакана ожидается корректный snapshot. |
| `disconnected` | Соединение WebSocket неактивно. |

При стандартных настройках первичный сбор базы RVOL может занимать до 21 минуты: нужно дождаться 20 полных прошлых минут и начала текущей. После переподключения или обнаруженного разрыва этот период начинается заново. Значения, для которых не хватает данных, не заменяются нулями или оценками.

## Запуск

Требуется Go 1.23 или новее.

```sh
git clone https://github.com/Quantum103/Scrinner_PAMPA.git
cd Scrinner_PAMPA
```

### PowerShell

```powershell
Copy-Item .env.example .env
Get-Content .env | ForEach-Object {
    if ($_ -match '^\s*([^#][^=]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($matches[1].Trim(), $matches[2].Trim(), 'Process')
    }
}
go run ./cmd/volume-trader
```

### Linux / macOS

```sh
cp .env.example .env
set -a
. ./.env
set +a
go run ./cmd/volume-trader
```

Для запуска без сетевых запросов:

```powershell
$env:MARKET_DATA_ENABLED = "false"
go run ./cmd/volume-trader
```

Остановить сервис можно через `Ctrl+C`. REST и WebSocket работают только с публичными endpoint; API-ключи, приватные потоки и размещение ордеров отсутствуют.

Приложение читает переменные окружения напрямую и не загружает `.env` самостоятельно. Файл `.env` находится в `.gitignore`.

## Что пока не реализовано

- Генерация торговых сигналов на основе рассчитанных метрик (сам анализатор реализован, но торговая стратегия пока не подключена).
- Торговая стратегия и генерация сигналов.
- Виртуальные ордера, позиции и расчёт PnL.
- Автоматическое восстановление пропущенного окна сделок из внешнего источника.
- Реальная торговля, приватные API и Telegram-уведомления.
